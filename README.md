# TradeArena

Учебный биржевой симулятор на Flutter с сервером Dart/Shelf и SQLite.
Каждому аккаунту принадлежит отдельный портфель на $10 000. Поддерживаются
рыночные и лимитные ордера, комиссия 0,1%, резервы средств и акций,
отмена заявок, сброс портфеля и рейтинг зарегистрированных пользователей.

## Запуск в Android Studio

Откройте корень проекта, где находятся `pubspec.yaml` и `lib/main.dart`.
Требуется Flutter с Dart, совместимым с `sdk: ^3.13.5`.

В отдельном терминале запустите сервер:

```powershell
cd C:\dev\trade_arena\server
dart pub get
dart run bin/server.dart
```

Проверка сервера: `http://localhost:8080/health`.
База `server/app.db` создаётся автоматически и сохраняется между запусками.

В корне проекта:

```powershell
flutter pub get
flutter run
```

В Android Studio выберите Android-эмулятор и конфигурацию запуска `lib/main.dart`.
Для нового пользователя сначала нужна регистрация. Вход с любыми данными больше
не работает. После регистрации создаётся пустой портфель с балансом $10 000.
Токен сохраняется между запусками; пароль на устройстве не хранится.
Выход и ответ сервера `401` очищают сессию и возвращают экран входа.

Эмулятор использует `http://10.0.2.2:8080` для доступа к компьютеру.
Для телефона укажите доступный с устройства адрес сервера:

```powershell
flutter run --dart-define=API_BASE_URL=http://192.168.1.10:8080
```

Телефон и компьютер должны находиться в одной сети. В debug-сборке разрешён
HTTP для локального учебного сервера. Для браузера адрес по умолчанию —
`http://localhost:8080`.

Если на Windows `flutter pub get` сообщает о символических ссылках, для
подготовки Android выполните в том же терминале:

```powershell
$env:FLUTTER_WINDOWS = 'false'
flutter pub get
```

Это отключает Windows-цель только в текущем терминале, системные настройки
не меняются. Дождитесь успешного завершения: прерванный `pub get` может оставить
Android без регистрации плагинов. После этого можно запускать приложение
обычной кнопкой Android Studio.

## Данные и устройство проекта

```text
Экраны → TradingModel → TradingRepository → HttpTradingRepository → сервер
                                                                    ↓
                                              торговые расчёты + SQLite
```

`TradingModel` публикует согласованный снимок через ChangeNotifier и Provider.
Покупка обновляет деньги, позицию и историю одной серверной транзакцией.
Списки доступны только для чтения. Смена пользователя создаёт новую модель
состояния, поэтому данные предыдущего аккаунта не переходят в новую сессию.

На сервере деньги хранятся в целых центах. Торговые расчёты отделены от HTTP
и SQL, а криптографические операции — от обработчиков авторизации.
У дневных заявок срок действия заканчивается в 00:00 UTC; проверка выполняется
при следующем обращении к торговым данным. Отменённые заявки остаются в истории.

Котировки пока фиксированы из ЛР4, это не реальные текущие цены.
Внешние котировки, конвертация валют и новости запланированы следующим этапом.
Новостная лента и история цен на этом этапе пустые.
Mock-хранилище осталось только в `test/support` для автономных тестов.

## API

Контракт находится в [openapi.yaml](openapi.yaml).

- `/auth/register`, `/auth/login`, `/me` — аккаунты и JWT.
- `/trading/snapshot` — согласованное состояние текущего пользователя.
- `/assets` — каталог, серверный поиск и фильтры.
- `/portfolio`, `/positions`, `/portfolio/reset` — свой счёт.
- `/orders`, `/orders/{id}` — создание, чтение, изменение и отмена заявок.
- `/notes`, `/files` — исходные маршруты учебного примера PAM.

Списки `/assets`, `/orders` и `/notes` принимают `page`, `limit`, `search` и
возвращают `{items, page, limit, total}`. В текущем интерфейсе торговли используется
полный снимок; серверная пагинация доступна через отдельные маршруты.
`DELETE /orders/{id}` возвращает снимок с кодом 200; `DELETE /notes/{id}` — 204 без тела.
Чужой ордер или заметка возвращают 404. Данные доступа и расчёты определяет сервер.

Параметры запуска сервера описаны в [server/README.md](server/README.md).

## Проверки

```powershell
# В корне проекта
flutter analyze --no-pub
flutter test --no-pub
flutter build apk --debug --no-pub

# С запущенным сервером и Android-эмулятором
flutter test integration_test/backend_test.dart -d emulator-5554 --no-pub

# В server, при остановленном сервере на Windows
dart analyze
dart test
```

Серверные тесты проверяют авторизацию, CRUD, разграничение доступа,
покупки и продажи, резервы, откат ошибочной заявки, сброс, срок действия,
параллельные операции, поиск и пагинацию более двадцати ордеров.
Тесты Flutter проверяют HTTP-ошибки, токены и торговые сценарии интерфейса.
Android-тест использует настоящий сервер и проверяет регистрацию, покупку,
восстановление сессии и смену аккаунта.
