# TradeArena

Учебный биржевой симулятор на Flutter: рынок США, Индии и Европы,
виртуальный портфель, рыночные и лимитные заявки, новости и рейтинг.
L4 продолжает тот же проект L2/L3 и историю Git.

## Запуск

Нужен Flutter с Dart, совместимым с `sdk: ^3.13.5` из pubspec.yaml.

```sh
flutter pub get
flutter run -d chrome
```

Вход и регистрация проверяют только поля (реальная авторизация — L5).
Для входа подойдёт корректный email и пароль от шести символов.
Данные демонстрационные и хранятся в памяти: перезапуск возвращает seed L2.

## Архитектура L4

```text
Экраны / AppShell
    │ watch в build, read в обработчиках, Consumer для badge
    ▼
TradingModel (ChangeNotifier)
    │ DI через конструктор; Future<Result<T>>
    ▼
TradingRepository (интерфейс)
    ▲ implements
MockTradingRepository (память, задержка 800 мс, управляемая ошибка)
    │
    ▼
mock_data.dart (исходные данные L2)
```

main.dart выбирает реализацию. Модель не импортирует mock и виджеты;
экраны и утилиты не импортируют seed. Коллекции снимка доступны только
для чтения. Сделка возвращает снимок целиком: баланс, позиции и ордера
попадают к подписчикам одновременно, без второго запроса после записи.
Repository предоставляет CRUD ордеров: fetchAll, fetchById, create,
update, delete, а также resetPortfolio. delete означает отмену
ожидающего ордера с сохранением истории. Методы изменения возвращают
Result<TradingSnapshot>, поскольку затрагивают несколько сущностей.

На L5 добавляется HTTP-реализация контракта и меняется её выбор в main.dart;
демонстрационный переключатель mock в профиле удаляется.

## Правила торговли

- Комиссия — 0,1 %. Сумма, комиссия и итог округляются до цента при операции.
- Рыночный ордер исполняется сразу по текущей демонстрационной котировке.
- Лимитный ордер исполняется сразу, если текущая цена выгоднее лимита;
  иначе получает статус «Ожидает».
- Ожидающая покупка резервирует сумму и комиссию. Продажа резервирует акции.
  Повторно потратить резерв нельзя; отмена освобождает его.
- Покупка создаёт или увеличивает позицию, обновляя среднюю стоимость с комиссией.
  Продажа уменьшает позицию; нулевой остаток удаляется.
- Дневной ордер истекает в полночь; проверка выполняется при следующем запросе.
  Котировки не меняются автоматически: внешнего рынка и фонового исполнения в L4 нет.
- Сброс после подтверждения возвращает $10 000 и удаляет позиции и историю.
- Рейтинг и профиль рассчитываются из текущего портфеля. Список содержит 10
  демонстрационных участников. График — за день, рейтинг — за всё время:
  недоступные исторические периоды больше не представлены пустыми переключателями.

## Проверка ошибок и защита

1. Войти и открыть рынок: виден список, поиск и фильтры.
2. Купить одну TSLA: новая позиция появляется в деталях и портфеле,
   число сделок и стоимость обновляются в рейтинге и профиле.
3. Создать лимитную покупку TSLA по $50: счётчик ожидающих ордеров растёт.
4. В портфеле нажать на ожидающий ордер и подтвердить отмену:
   статус меняется, счётчик уменьшается, резерв освобождается.
5. В профиле включить «Симулировать сбой сети», затем нажать обновление.
   После spinner появляется ошибка с «Повторить». Выключить сбой и повторить.
   Переключатель доступен и на экране ошибки.
6. При включённом сбое отправить валидную форму: сообщение об ошибке,
   введённые данные остаются, ордер не создаётся. Выключить сбой и повторить.
7. Подтвердить сброс портфеля: позиции и ордера исчезают, баланс $10 000.

## Проверки и отчёт

```sh
flutter analyze --no-pub
flutter test --no-pub
flutter build web --release --no-pub
# Реальные рендеры Flutter для отчёта (не макеты):
flutter test --no-pub test/ui_flow_test.dart --dart-define=CAPTURE_L4=true
```

Тесты проверяют расчёты, резервы, обновление и отмену ордеров, сетевые ошибки,
неизменяемость снимков, параллельные запросы и пользовательский поток через UI.
Снимки лежат в docs/l4/screenshots. PDF и исходник генератора сохраняют
оформление предоставленного отчёта L3; см. docs/l4 и output/pdf.
